# SpeakCoach

> AI English speaking practice agent. Web (React) → Java Spring Boot (auth + business) → Python FastAPI + LangGraph (AI workflow) → GPT-SoVITS (local TTS) → MySQL (long-term memory) + Redis (LangGraph checkpoint).

See `AGENTS.md` for the full architecture, package map, service-layer contracts, and the on-call playbook. The plan lives at `.omc/plans/speakcoach-mvp.md`.

## Architecture rules

1. The frontend talks to **Java only**. Python is internal — never exposed to the browser.
2. Java validates `session.userId == currentUserId` on every `/api/chat` and `/api/audio/**` request.
3. LangGraph `thread_id` is `thread:{user_id}:{session_id}` to guarantee per-user checkpoint isolation.
4. Every LangGraph node writes an `audit_log` row (input JSON, output JSON, latency_ms, model_name, prompt_version) — currently a local log stub, ready to forward to Java's `/internal/audit` endpoint.
5. Audio is generated by Python, persisted to `storage/audio/`, and served by Java with a userId check.
6. The Java backend is built on Lombok + Spring Boot 3.3.4 + JDK 21. Lombok is wired explicitly via `<annotationProcessorPaths>` in `pom.xml` because the parent POM does not auto-register it on the processor path.
7. Persistence is **MyBatis-Plus** (Mappers under `com.speakcoach.mapper` extending `BaseMapper<T>`), not JPA. Entities are annotated with `@TableName` / `@TableId`; `userId` is an auto-increment `BIGINT`, while `sessionId` remains a UUID string. See `AGENTS.md` §11 for the migration note.

## Prerequisites (native local install — no Docker)

> **IMPORTANT — Java 21+ required.** The Java backend is built on
> **Lombok 1.18.34 + Spring Boot 3.3.4 + JDK 21**. **Java 17 will not
> work** — the build will fail with `IncompatibleClassChangeError` (and
> any JVM crash will leave `hs_err_pid*.log` files in `backend-java/`).
> Verify your active JDK before continuing:
>
> ```bash
> java -version
> # → openjdk version "21.x.x" ...
> ```
>
> If you have multiple JDKs installed, point `JAVA_HOME` at the JDK 21
> install (see the "Running the stack" section below).

| Tool       | Version | Notes                                            |
|------------|---------|--------------------------------------------------|
| Java       | 21+     | `java -version` — **required**, see warning above |
| Maven      | 3.9+    | or use the bundled `./mvnw`                      |
| Python     | 3.11+   | venv recommended                                 |
| Node.js    | 20+     | LTS                                              |
| MySQL      | 8.0+    | running on `localhost:3306`, db `speakcoach`     |
| Redis      | 7+      | running on `localhost:6379` (optional)           |
| GPT-SoVITS | latest  | local inference endpoint, base URL via `.env`    |

## Running the stack

Three terminals:

```bash
# Terminal 1 — Java backend
cd backend-java
# Ensure JDK 21 is the active one (Lombok 1.18.34 + Spring Boot 3.3.4 need it).
$env:JAVA_HOME = "E:\develop\java\jdk-21"
mvn clean compile -DskipTests
mvn spring-boot:run
# → http://localhost:8080

# Terminal 2 — Python AI service
cd backend-python
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env       # then edit
uvicorn app.main:app --host 0.0.0.0 --port 9000 --reload
# → http://localhost:9000 (internal only)

# Terminal 3 — React frontend
cd frontend
npm install
npm run dev
# → http://localhost:5173
```

## Day-1 smoke test

A complete end-to-end curl walkthrough is documented in `AGENTS.md` §7. Quick version:

```bash
# 1. Register (MyBatis-Plus stack: email is required, userId is an auto-increment Long)
curl -i -X POST http://localhost:8080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"smoketest","email":"smoketest@e2e.local","password":"test1234"}'
# → 201 {userId: <long>, username, email, token}

# 2. Login
curl -i -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"smoketest","email":"smoketest@e2e.local","password":"test1234"}'
# → 200 {userId: <long>, username, email, token}

# 3. /me without / with auth
curl -i http://localhost:8080/api/auth/me                                              # → 401
curl -i http://localhost:8080/api/auth/me -H "Authorization: Bearer <token>"          # → 200

# 4. Create a session, read it back (sessionId is a UUID string)
curl -i -X POST http://localhost:8080/api/sessions \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"scene":"interview"}'                                                           # → 201
curl -i http://localhost:8080/api/sessions/<sessionId> \
  -H "Authorization: Bearer <token>"                                                   # → 200

# 5. Chat (delegates to Python on :9000). sessionId is a UUID string.
curl -i -X POST http://localhost:8080/api/chat \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d "{\"sessionId\":\"<sessionId>\",\"userText\":\"Hello, my name is John.\"}"        # → 200

# 6. Finish the session
curl -i -X POST http://localhost:8080/api/sessions/<sessionId>/finish \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"summary":"Smoke test complete."}'                                              # → 200

# 7. Audio without auth (real URLs use /api/audio/<userId>/<sessionId>/turn_1.wav)
curl -i http://localhost:8080/api/audio/1/<sessionId>/turn_1.wav                        # → 401 / 403
```

## What's in this build

- **Java backend**: 6 service interfaces (`AuthService`, `SessionService`, `TurnService`, `TtsService`, `PythonClient`, `AuditService`) + 6 concrete `*Impl` classes. Plus a `UserAbilityProfileServiceImpl`, an `UserController`, an `AudioController`, a `common/` module (`ApiResponse`, `BusinessException`, `UserContext`, `JwtUtil`, `RequestIdFilter`, `CommonConfig`, `GlobalResponseAdvice`), and a `GlobalExceptionHandler` that maps every error to a uniform envelope.
- **Python AI service**: a complete FastAPI + LangGraph workflow with real LLM calls (OpenAI / Anthropic / MiniMax / Stub), real GPT-SoVITS HTTP client (with silence-WAV fallback), real checkpointer factory (memory / Redis), versioned prompts, and a tolerant JSON parser for LLM replies. Endpoints: `/internal/turn`, `/internal/health`, `/internal/turn/{thread_id}/history`, `/internal/run-event-batch`.
- **TTS**: GPT-SoVITS client + 400 ms silence WAV fallback. Writes under `AUDIO_STORAGE_PATH/{user_id}/{session_id}/turn_{n}.wav` and returns `/api/audio/{user_id}/{session_id}/turn_{n}.wav`.
- **MySQL schema**: `user`, `speaking_session`, `speaking_turn`, `audit_log`, `user_ability_profile` (see `db/init.sql`).
- **Documentation**: `AGENTS.md` is the canonical architecture / package map; this README is the operator's quick-start.

## Known limitations

See `AGENTS.md` §8 for the full list. The headlines:

- TTS falls back to a 400 ms silence WAV when GPT-SoVITS is unreachable.
- Without an LLM API key the service uses a deterministic `StubChatModel` (so the workflow still runs end-to-end with placeholder replies).
- LangGraph checkpointing is in-memory by default; set `CHECKPOINT_BACKEND=redis` to persist.
- The Maven build requires **JDK 21** (Lombok 1.18.34 / Spring Boot 3.3.4). JDK 17 will not work.
- `application.yml` ships with a dev-only datasource password and JWT secret; override in production.
